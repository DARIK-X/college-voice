# Выборы президента колледжа · Laravel + Tailwind

Полный проект на Laravel 13, PHP 8.3+ и Tailwind 3.4. Фотографии семи кандидатов извлечены из предоставленного PDF и сохранены в PNG. Фон — предоставленный GIF. Зависимости устанавливаются командами ниже.

## Если отсутствует bootstrap/cache (PowerShell)

Выполните из корня проекта:

```powershell
$folders = @("bootstrap/cache", "storage/framework/cache/data", "storage/framework/sessions", "storage/framework/views", "storage/logs")
foreach ($folder in $folders) { New-Item -ItemType Directory -Force -Path $folder | Out-Null }
php artisan package:discover
php artisan key:generate
php artisan optimize:clear
```

Правильные команды очистки: `php artisan cache:clear` и `php artisan route:clear`. Команд `cach:clean` и `route:clean` нет. Генерируйте ключ только при первой установке, когда APP_KEY ещё пуст.

## Локальный запуск

Нужны PHP 8.3+ с SQLite, mbstring, openssl, fileinfo, XML, Composer 2 и Node.js 17.9.1.

```bash
composer install
cp .env.example .env
php artisan key:generate
```

Для локального HTTP в `.env` установите `SESSION_SECURE_COOKIE=false`, `APP_URL=http://localhost:8000`, `APP_ENV=local`. Создайте пустой файл `database/database.sqlite` (например, `touch database/database.sqlite` в Linux/macOS).

```bash
php artisan migrate --seed
php artisan storage:link
php artisan admin:create
npm ci
npm run build
php artisan serve
```

`admin:create` запрашивает email и скрытый пароль (минимум 12 символов). Общего пароля по умолчанию нет. Регистрации учеников нет.

## Страницы

- `/` — список кандидатов и голосование с подтверждением.
- `/result` — публичная диаграмма, только проценты без количества голосов.
- `/admin/login` — вход администратора.
- `/admin/panel` — запуск, завершение и журнал последних 30 действий.
- `/admin/candidate` — создание, редактирование, снятие/удаление и ручные корректировки.

Публичные страницы не содержат ссылок на админку. Скрытый адрес не заменяет авторизацию: все административные операции защищены проверкой прав на сервере.

## Один голос

Сервер выдаёт зашифрованную HttpOnly-cookie с случайным UUID на три года. В БД хранится HMAC идентификатора. Уникальный индекс `(election_id, device_hash)` и транзакция с блокировкой предотвращают два голоса одного браузера, в том числе при повторной отправке. POST без ранее выданной cookie отклоняется.

Это ограничение одного браузера, а не доказательство одного физического устройства: удаление cookie, инкогнито и другой браузер позволяют получить новый идентификатор. Надёжное «один ученик — один голос» требует индивидуальных одноразовых кодов или идентификации. IP не используется как уникальный избиратель, чтобы не блокировать школьную Wi-Fi сеть. Одноразовые коды в этой версии не реализованы.

## Управление

Запуск и завершение требуют пароль и точное слово НАЧАТЬ / ЗАВЕРШИТЬ. Повторное открытие сохраняет результаты и уже использованные идентификаторы. Новый цикл выборов через интерфейс не создаётся. Голосование изначально закрыто (подготовка).

Корректировки голосов доступны в админке: число со знаком, причина не короче 10 символов, повторный ввод пароля. Изменения сохраняются отдельно от бюллетеней; журнал хранит администратора, время, прежнее значение, изменение и причину. Реальные бюллетени уменьшить через корректировку нельзя. Публичный итог включает корректировки. Кандидат с голосами при удалении снимается с выборов и остаётся в результатах, чтобы сохранить историю. Удаление кандидата без голосов также журналируется.

## Обновление результатов

Fetch раз в 5–6 секунд, без перезагрузки страницы. Запросы не перекрываются, при скрытой вкладке приостанавливаются, при ошибке увеличивается интервал повтора и отображается сообщение. Агрегат кешируется на 2 секунды; после изменений кеш сбрасывается. График и полосы анимируются. Если сеть недоступна, последние данные остаются на экране.

## Продакшен и нагрузка

Для примерно 1000 голосующих в день используйте Nginx + PHP-FPM, MySQL 8/InnoDB либо PostgreSQL, Redis для кеша и сессий, HTTPS и OPcache. Это целевой сценарий, а не подтверждённый нагрузочным тестом предел. 1000 посетителей за день и 1000 одновременных посетителей — разная нагрузка; 1000 открытых вкладок дают примерно 170–200 запросов результатов в секунду. Перед выборами проведите тест на вашем сервере с ожидаемым пиковым числом зрителей.

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://your-domain.example
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=elections
DB_USERNAME=elections
DB_PASSWORD=YOUR_SECRET
CACHE_STORE=redis
SESSION_DRIVER=redis
SESSION_ENCRYPT=true
SESSION_SECURE_COOKIE=true
REDIS_CLIENT=phpredis
```

Установите PHP Redis extension, настройте Redis и ограничьте доступ к БД. Не меняйте APP_KEY во время выборов: это инвалидирует cookie. Корень веб-сервера строго `public/`. `.env`, база данных, storage и исходники не должны быть доступны через веб. Для файлов `/storage` запретите исполнение PHP и любых скриптов в конфигурации Nginx/Apache. Настройте доверенные прокси только на свои адреса, чтобы HTTPS и rate limiting работали правильно. Установите лимит тела запроса около 5 МБ.

```bash
composer install --no-dev --optimize-autoloader
npm ci
npm run build
php artisan migrate --force
php artisan db:seed --force
php artisan storage:link
php artisan admin:create
php artisan optimize
```

Seed идемпотентен и не создаёт администратора. Существующую БД сначала резервируйте, затем запускайте обычные миграции. `migrate:fresh` удаляет данные — используйте только на отдельной тестовой БД. В архив не включены исходные `.env`, база данных, сессии и загруженные ранее файлы.

Включены CSRF-защита Laravel, регенерация сессии при входе, ограничение попыток входа/голосования, проверка MIME фотографий (SVG запрещены), экранирование Blade, CSP, HSTS на HTTPS и защитные заголовки. Из-за CSP для локального просмотра используйте `npm run build`, а не Vite HMR. Повторный ввод пароля защищает опасные административные действия, но не заменяет MFA.

Регулярно делайте резервные копии БД и загруженных фото. Доступ к БД и журналу предоставляйте только ответственным лицам. Время журнала — UTC. Встроенных средств редактирования/удаления журнала нет. Прямой доступ владельца БД позволяет менять её содержимое.

## Проверка

```bash
php artisan test
npm run build
```

Тесты используют отдельную SQLite БД в памяти. Проверяются повторный голос, отсутствие cookie, закрытые выборы, разные браузеры, снятый кандидат, права администратора, вход/выход, подтверждение управления, журнал корректировок, сохранение голосов при снятии и проценты. Стандартный тест главной страницы можно запускать вместе с ними.


## Проверка этой версии

Проверено на PHP 8.3.32: 23 теста, 97 проверок — успешно; Composer check-platform-reqs — успешно. Production-сборка выполнена на Node.js 17.9.1. Используются Vite 4.5 и Tailwind 3.4. IP не ограничивает количество голосов. Регистрации и одноразовых кодов нет, идентификатор браузера хранится в cookie. Проверка в браузере и нагрузочный тест на целевом сервере не проводились.

## ФИО и группа при голосовании

Перед подтверждением ученик обязательно вводит ФИО (5–160 символов) и название группы (2–40 символов). Обязательность проверяется браузером и сервером. Данные сохраняются вместе с голосом. В админ-панели отображается список проголосовавших с пагинацией по 50 записей. В публичных результатах ФИО и группы избирателей не выдаются.

ФИО и группа вводятся самостоятельно и не подтверждают личность. Ограничение повторных голосов по-прежнему работает по cookie. Повторение ФИО не блокируется, чтобы не блокировать однофамильцев и тёзок.

При обновлении существующего проекта сохраните свою `.env`, БД и пользовательские загрузки. Замените исходники и собранную папку `public/build`, затем выполните:

```bash
php artisan migrate
php artisan optimize:clear
```

Новая миграция добавляет поля без удаления прежних голосов. Для старых записей ФИО и группа остаются пустыми. Не запускайте migrate:fresh и не заменяйте свою БД пустым файлом из архива.

## Публичные результаты

На странице /result и в /results/data доступны только проценты. Общее число голосов, число голосов кандидатов и корректировки в публичный API не выдаются. Диаграмма строится по процентам; числовые итоги остаются доступны администратору.
